# Самообучающийся харнесс AGONTS — Полное руководство (RU)

> English version: [`HARNESS.en.md`](HARNESS.en.md) · Философия: [`PHILOSOPHY.md`](PHILOSOPHY.md)

Это полный разбор. Прочитай сверху вниз — и поймёшь каждый хук, каждый скрипт,
каждый кусок состояния и, главное, *почему* каждый из них существует.

---

## 0. Что такое «харнесс»

Харнесс — это детерминированная обвязка вокруг недетерминированного агента.
Модель предлагает; харнесс располагает. Каждое действие агента — чтение
промпта, запись файла, запуск команды, завершение хода — проходит через хук,
которым управляет харнесс.

Claude Code отдаёт **события** жизненного цикла. Харнесс привязывает к каждому
небольшой shell-скрипт в `.claude/settings.json`:

| Событие | Когда срабатывает | Наш хук | Может блокировать? |
|---|---|---|---|
| `SessionStart` | открытие / возобновление / после компакции | `session-start.sh` | нет (только инъекция) |
| `UserPromptSubmit` | каждое сообщение пользователя | `prompt-context.sh` | нет (только инъекция) |
| `PreToolUse` | перед запуском инструмента | `guard-write.sh`, `guard-bash.sh` | **да** (`exit 2`) |
| `PostToolUse` | после успеха инструмента | `format-file.sh`, `lint-file.sh`, `arch-gate.sh`, `track-mcp.sh` | обратная связь (`exit 2`) |
| `Stop` | агент пытается завершить ход | `check-boundaries.sh` → `evidence.ts` | **да** (`exit 2`) |
| `SessionEnd` | сессия закрывается | `session-end.sh` → `retro.ts` | нет |

Код возврата — это весь контракт:

- `exit 0` — разрешить, молчать.
- `exit 2` — **блок**, и stdout/stderr возвращаются агенту, чтобы он сам
  исправился. Это рычаг, превращающий совет в физику.

## 1. Доктрина (три правила, формирующие всё)

Каждая часть харнесса подчиняется трём правилам, дистиллированным из докладов в
[`PHILOSOPHY.md`](PHILOSOPHY.md):

### Правило 1 — Принуждай, а не инструктируй
Правило в `CLAUDE.md` соблюдается ~80% времени и резко деградирует после ~15
вызовов инструментов (разбавление внимания: токены системного промпта теряют
вес по мере заполнения окна историей вызовов). Правило в `PreToolUse`-хуке
соблюдается на 100%, потому что правка физически не может лечь, пока хук не
вернёт `exit 0`. Поэтому всё, что *может* быть хуком, *является* хуком.

### Правило 2 — Направляй, а не предписывай
Стена «делай это, делай то» отправляет модель за призраками — один
переусердствовавший скилл уронил задачу с 97% до 77% корректности. Харнесс
инжектит **одну самую релевантную граблю** в момент, когда это важно, а не весь
свод правил. Смотри проактивную инъекцию граблей в §2 (нога 4).

### Правило 3 — Измеряй, а не предполагай
Нельзя знать, какие из 22 гейтов помогают, а какие вредят, пока не считаешь.
Каждое срабатывание гейта инкрементит счётчик. Retro читает счётчики и говорит,
какие гейты *горячие* (срабатывают постоянно → правило неясно, чини корень) и
какие *мёртвые* (не срабатывают никогда → шум, предложи удалить). **Любой сбой —
это баг харнесса.**

## 2. Четыре ноги

### Нога 1 — ПРЕДОТВРАТИ (жёсткие гейты на этапе записи)

`guard-write.sh` запускается на каждом `Write`/`Edit`. Он делит правила на два
уровня:

- **Блокирующие (объективные, однозначные):** `any`, `as unknown as`, non-null
  `!`, `@ts-ignore`, слабые типы `Function`/`Object`/`{}`, `debugger`,
  **вложенный тернарник**, расширения в импортах, глубокие импорты мимо бочки
  пакета, inline-Zod вне `@agonts/contracts`, Zod `message:` вместо `error:`,
  `console` в чистом слое, файлы секретов/credentials. Каждое зовёт `hook_fail`
  → `exit 2`.
- **Advisory (специфичные для стека, размытые):** кириллица вне i18n,
  отсутствующий `workspaceId` в методе репозитория, файлы >400 строк, папки >5
  записей, магические числа, захардкоженные URL, `process.env` вне config.
  Каждое зовёт `hook_warn` → `exit 0`. Правка ложится; агент видит лишь нудж.

Зачем разделение? **Ложный блок бесит оператора.** В момент, когда гейт ошибочно
останавливает легитимную работу, человек отключает весь харнесс. Поэтому жёсткая
линия проводится только там, где правило объективно решаемо из текста.

`guard-bash.sh` — стена команд. Блокирует глобально запрещённые операции:
`git stash` (без исключений — прячет работу и легко потерять), `--no-verify`,
`git reset --hard`, `git clean -f`, `git branch -D`, force-push,
`npm`/`yarn`/`pnpm` (стек залочен на `bun`), `npx` (используй `bunx`) и пайп
удалённого скрипта прямо в шелл. Делает и одну *measure*-вещь: если агент
запускает `grep`/`rg`, пока индекс serena устарел, инкрементит
`search:grep-before-serena` — без блока, просто отметка для retro.

### Нога 2 — ДОКАЖИ (гейт доказательства)

Самая хитрая нога. Проблема: агенты говорят «готово, тесты прошли», ничего не
запустив. Первый фикс Ника Ниси — файл-маркер `.case-tested`, но агент может
`touch`-нуть маркер. Значит маркер должен быть **неподделываемым**.

`scripts/evidence.ts`, срабатывает на `Stop`:

1. Вычисляет набор изменённых исходников `.ts/.tsx` (исключая test/generated).
2. Хеширует их *содержимое* в 16-символьный tree-хеш (`sha256` от пути + байт).
3. Если прошлая зелёная отметка имеет тот же хеш → уже доказано, мгновенный
   `exit 0` (дорогой typecheck не перезапускается на неизменном коде).
4. Иначе запускает `bun nx run-many -t typecheck` и считает ошибки.
5. **Храповик:** `errors <= baseline` → пишет зелёное, `exit 0`. `errors >
   baseline` → ход добавил НОВУЮ поломку → **блок Stop (`exit 2`)** и возврат
   первых ошибок.

Хеш привязан к реальным байтам файла, так что нельзя завершить ход с заявлением
об успехе, пока тронутый код не компилируется, и нельзя подделать доказательство
через `touch`. Существующий долг амнистирован (`baseline`); фатален только новый.

**Предохранитель:** если идентичное сломанное дерево блокируется 3 раза без
прогресса правок, evidence сам деградирует до advisory (`exit 0` с
предупреждением), чтобы агент не застрял навсегда.

### Нога 3 — ИЗМЕРЬ (субстрат аккумуляторов)

Самая тихая нога и та, что делает остальные три умными. Живёт в `_lib.sh` и
состоит из двух крошечных функций:

- `hook_bump <key>` — инкрементит `.hookstate/counters/<key>` на единицу.
  Fire-and-forget; никогда не ломает вызывающий хук.
- `hook_count <key>` / `hook_top_counter <prefix>` — читают счётчики обратно.

Каждый раз, когда `hook_fail` блокирует правку, он инкрементит **два** счётчика:

- `guard:<label>` — грубый, напр. `guard:write`, `guard:bash`. Позволяет retro
  отличить *горячие* гейты (срабатывают постоянно) от *мёртвых* (не срабатывают
  никогда).
- `gotcha:<reason-head>` — точный, первые 60 символов причины блока. Позволяет
  проактивному инжектору вынести одну самую частую граблю в следующий промпт.

Счётчики — это gitignored runtime-состояние в `.hookstate/counters/`. Они —
*сырой сигнал*; две другие функции харнесса — проактивная инъекция и retro —
просто два разных читателя того же сигнала. Это дешёвый первый взнос на ногу
«измерь» по Нику: ни eval-фреймворка, ни дашборда — лишь папка целых чисел,
которую майнит остальная система.

### Нога 4 — УЧИСЬ (retro + проактивная инъекция)

Два читателя превращают сырые счётчики в изменение поведения.

**Проактивная инъекция** (`prompt-context.sh`, на каждом промпте). Читает один
самый горячий счётчик `gotcha:` и, *если он сработал ≥3 раз за окно*, инжектит
именно эту граблю как точечное напоминание:

```
RECURRING GOTCHA (you hit this 4x — fix it at the source this time):
nested-ternary---extract-to-an-if-switch-or-a-lookup-map-for
```

Это Правило 2 в действии — направляй, не предписывай. Не весь свод; *одно*
правило, которое ты постоянно нарушаешь, вынесенное *до* правки, а не только
заблокированное после. Тот же хук обеспечивает каденс инструментов: если serena
не запускалась 15 мин или qdrant 20 мин (по таймстемпам `track-mcp.sh`), он
инжектит нудж использовать индекс перед grep.

**Retro** (`scripts/retro.ts`, запускается автоматически на `SessionEnd` и по
запросу через скилл `harness-retro`). Майнит JSONL транскрипта сессии плюс
счётчики и выдаёт находки:

| Находка | Как детектится | Что значит |
|---|---|---|
| **doom-loop** | один `tool_use` (имя + ввод) ≥3× | агент крутился на месте — хук должен был поймать раньше |
| **hot-guard** | счётчик `guard:*` ≥5 | правило неясно или воркфлоу с ним борется → чини *корень* |
| **dead-guard** | известный label гейта не сработал | возможно шум → предложи удалить |
| **grep-before-serena** | `search:grep-before-serena` > 0 | индекс пропустили → усиль serena-first |

Пишет карточку памяти `harness_retro_<date>.md` и добавляет строку в `MEMORY.md`,
**только если есть реальный сигнал** (чистый прогон не оставляет шума). На
`SessionEnd` затем сбрасывает окно счётчиков, чтобы следующая сессия измеряла с
нуля.

**Кросс-сессионный реестр продвижения (ledger).** Счётчики сбрасываются каждую
сессию; реестр (`.hookstate/harness-patterns.jsonl`) — нет. Он отслеживает, в
скольких *разных* сессиях повторилась каждая находка. На 3+ сессиях паттерн
помечается к **продвижению** — поднять в `CLAUDE.md` или карточку правила. Это
мост от «я наткнулся один раз» к «это системная дыра харнесса, достойная
постоянного правила». Критично: retro **предлагает** продвижение. Он никогда сам
не правит `CLAUDE.md`. Человек остаётся выше по стеку и одобряет.

## 3. Группа поддержки

Не каждый хук — нога. Ещё три держат петлю гладкой:

- **`session-start.sh`** — на открытии/возобновлении/компакции инжектит
  ориентацию по репо: ветку, число незакоммиченных, недавние коммиты, карту
  пакетов/приложений и несущие архитектурные инварианты. Ценнее всего сразу
  после компакции контекста, когда агент потерял ориентиры.
- **`format-file.sh`** — после каждой записи прогоняет `biome format --write` по
  тронутому файлу. Никогда не блокирует. Агент не тратит ход на форматирование.
- **`lint-file.sh`** — после каждой записи прогоняет `biome lint`. Если есть
  реальные диагностики, `exit 2` возвращает их, чтобы агент исправился сразу, а
  не обнаружил на CI.
- **`arch-gate.sh`** + **`arch-gate.ts`** — храповик архитектурного долга. Это
  *шаблон*, который копирует весь харнесс. Паттерны детекции живут в
  `arch-gate.rules.json` (данные), раннер считает и сравнивает с
  `arch-baseline.json`. `count > baseline` → блок; `count < baseline` → проход +
  «запусти `--update`, чтобы зафиксировать выигрыш». Раннер свободен от литералов,
  которые ищет, поэтому не матчит собственный исходник.

## 4. Как ноги складываются в самообучающуюся петлю

Читай ноги как цикл обратной связи, а не чек-лист:

1. **Предотврати** останавливает очевидные ошибки на этапе записи. Но ловит лишь
   то, что объективно решаемо из текста одного файла.
2. **Докажи** ловит то, что предотвращение не может — кросс-файловую поломку
   типов, видимую лишь после всей правки. Гарантирует пол: ход компилируется.
3. **Измерь** наблюдает *всё* — какие предотвращения срабатывают, какие нет, где
   агент зацикливается. Без этого ты гадаешь, какие из 22 правил оправдывают себя.
4. **Учись** превращает наблюдение в изменение: предупреждает *до* правки о
   грабле, на которую ты постоянно наступаешь, и предлагает постоянные правила
   для системных дыр. Выход «учись» становится лучшим «предотврати».

Петля затягивается каждую сессию. Харнесс не просто останавливает плохой код —
он выясняет, *какие* правила важны, выносит их в нужный момент и просит человека
продвинуть те, что повторяются. Вот что значит «самообучающийся» здесь: умнеет
не модель, а **обвязка** — умнеет относительно модели.

## 5. Эксплуатация

```bash
# текущая отметка evidence
bun scripts/evidence.ts --status

# что изменилось + tree-хеш, без запуска typecheck
bun scripts/evidence.ts --self-test

# пере-базлайн evidence против текущего дерева (амнистировать текущий долг)
bun scripts/evidence.ts --reset

# ворклист архитектурного долга
bun scripts/arch-gate.ts --list
bun scripts/arch-gate.ts --list=<rule-id>

# зафиксировать снижение долга после выплаты
bun scripts/arch-gate.ts --update

# retro по новейшему транскрипту (только печать)
bun scripts/retro.ts

# retro с записью карточки памяти
bun scripts/retro.ts --write

# майнить конкретный транскрипт
bun scripts/retro.ts --file=~/.claude/projects/<slug>/<id>.jsonl

# начать свежее окно измерений
bun scripts/retro.ts --reset-counters
```

## 6. Расширение

Чтобы добавить новое правило предотвращения:

- **Объективно + решаемо из одного файла?** Добавь проверку `hook_has` в
  `guard-write.sh`, зовущую `hook_fail` (блок) или `hook_warn` (advisory).
- **Репо-широкое, в стиле храповика?** Добавь запись в `arch-gate.rules.json` и
  запусти `bun scripts/arch-gate.ts --update` для базлайна. Код раннера не
  трогаешь.
- **Команда к запрету?** Добавь строку `grep -qE … && hook_fail` в
  `guard-bash.sh`.

Каждый новый блок автоматически участвует в «измерь» (инкрементит счётчик) и
«учись» (retro отчитается, горячий он или мёртвый). Ты никогда не подключаешь это
вручную — оно вытекает из вызова `hook_fail`.
